C. MENGENAL CPU & REGISTER: TIM 3 PEMAIN

CPU (Central Processing Unit) bukan satu unit tunggal, melainkan tim 3 pemain yang saling bekerja sama memproses miliaran operasi per detik: Control Unit (CU), Arithmetic Logic Unit (ALU), dan Register.

🧩 Tiga Bagian Utama CPU

Control Unit (CU)

Sky • Mandor

Otak pengatur aliran instruksi dan pengirim sinyal kontrol. CU bertugas mengambil instruksi via Fetch, menerjemahkannya (Decode), dan mengatur urutan siklus kerja: "ALU hitung! Register simpan!". CU tidak melakukan perhitungan, melainkan mengarahkan semua komponen bekerja terkoordinasi.

Analogi: Mandor proyek — teriak "angkat bata!" / Sutradara film

Arithmetic Logic Unit (ALU)

Emerald • Mesin Hitung

Pusat eksekusi komputasi nyata. Bertanggung jawab mengeksekusi operasi matematika dasar ($+$, $-$, $\times$, $\div$) dan evaluasi logika perbandingan (AND, OR, NOT, $>$, $<$, $=$). Contoh: $25 + 15 = 40$ atau memeriksa apakah nilai $> 75$. ALU mampu mengeksekusi miliaran operasi per detik.

Analogi: Kalkulator super cepat — miliaran operasi per detik

Register (Memori Kilat)

Amber • Saku Cepat

Memori paling cepat di seluruh komputer (100x lebih cepat dari RAM, akses ~0.3 nanodetik), tetapi berukuran super kecil. Berfungsi menyimpan alamat memori, data aktif yang sedang dikerjakan, dan hasil perhitungan sementara sebelum disetor balik ke RAM.

Analogi: Buku catatan saku di kantong mandor — "Ambil di rak A3"
Cara Kerja Bareng Tim 3 Pemain CPU:

CU = Sutradara / Mandor yang memberi aba-aba, ALU = Aktor / Mesin Hitung yang melakukan komputasi, dan REGISTER = Catatan di kantong saku. Siklus ini berulang terus-menerus setiap siklus Fetch-Decode-Execute hingga perintah HALT (selesai).

5 Register Kunci dalam CPU yang Wajib Diketahui:

PC (Program Counter):

Menyimpan alamat memori instruksi berikutnya di RAM yang akan diambil.

IR (Instruction Register):

Menyimpan instruksi yang sedang didecode dan dianalisis oleh CU.

MAR (Memory Address Register):

Menampung alamat lokasi kotak memori di RAM yang akan dibaca atau ditulis.

MDR (Memory Data Register):

Menampung muatan data aktual yang baru ditarik dari RAM atau akan dikirim ke RAM.

ACC (Accumulator):

Tempat penampungan hasil sementara operasi perhitungan matematika yang baru dieksekusi ALU.

A. MODEL I-P-O & ALUR RESMI 5 TAHAP

Arsitektur adalah desain/strukturnya (seperti denah rumah, bukan batanya). Sedangkan Dinamika adalah alur/perjalanan datanya yang bergerak melintasi desain tersebut (I-P-O yang hidup).

Alur Resmi Fisik Komputer:
INPUT → [RAM] → CPU → [RAM] → OUTPUT

*Semua data WAJIB lewat RAM — baik saat masuk maupun keluar. Tidak ada jalan pintas Input → CPU!

📌 3 Prinsip yang Wajib Diingat:

1

RAM adalah HUB

Pusat pertemuan data. Input dan Output tidak boleh langsung ke CPU. Semua pertukaran wajib lewat RAM.

Input ↛ CPU & CPU ↛ Output
2

CPU Fokus Mengolah

Hanya 2 arah dengan RAM via Bus: pinjam data mentah & kembalikan hasil jadi. Tidak mengurus keyboard/layar.

RAM ⇄ CPU via Bus Sistem
3

Layar Ambil dari RAM

Monitor bukan menerima gambar dari CPU. Monitor melakukan polling RAM 60x/detik lalu merender piksel tampilan.

RAM → Output = Tampil Hasil

Aturan Emas: CPU itu "Sombong"!

CPU bersifat eksklusif. Perangkat input (keyboard/mouse) berjalan sangat lambat dalam milidetik, sementara CPU berdetak dalam hitungan nanodetik. Jika CPU menunggu input langsung, miliaran siklus kerja CPU akan terbuang percuma (idle). Karena itu, CPU hanya mau berurusan dengan RAM sebagai perantara sentral!

B. 4 KOMPONEN UTAMA KOMPUTER VON NEUMANN

Latar Belakang Sejarah (1945)

Dari Cabut Kabel Berhari-hari → Load File dalam Hitungan Detik

❌ Sebelum 1945 • Era ENIAC Ganti tugas = cabut-pasang kabel fisik. Operator harus melakukan rewiring manual selama berjam-jam hingga berhari-hari hanya untuk menjalankan 1 program baru.
✅ Sesudah 1945 • Stored Program Ide jenius John von Neumann: "Kenapa instruksi program tidak disimpan saja bersamaan dengan datanya di dalam memori?" Ganti program cukup muat file baru dalam hitungan detik!

🧩 4 Pilar Arsitektur Komputer:

1. Input Device

Amber • Masuk

Pintu masuk data tempat pengguna memberikan perintah. Mengubah aksi fisik menjadi sinyal listrik yang dititipkan dulu ke RAM.

Contoh: Keyboard, Mouse, Touchscreen, Mic, Scanner, Sensor IoT.

2. Main Memory (RAM)

Emerald • Hub

Gudang sementara & meja kerja volatile. Setiap sel memori memiliki alamat unik (seperti kotak 100, 200, 300).

Karakteristik: Volatile (hilang tanpa listrik), Super Cepat (~10ns), Akses Acak.

3. Central Processing Unit

Sky • Otak

Otak komputer — pusat hitung dan olah data yang mengeksekusi miliaran operasi per detik. Terdiri dari CU, ALU, dan Register.

Aturan: Hanya mengambil data dari RAM dan mengembalikan hasil ke RAM.

4. Output Device

Cyan • Keluar

Pintu keluar hasil yang menampilkan data hasil olahan dari RAM, bukan langsung dari CPU.

Contoh: Monitor, Layar HP, Speaker, Printer, Projector, Lampu LED.

Analogi Dokumen: RAM (Meja Kerja) vs Storage (Gudang Arsip)

RAM = Meja Kerja Dokumen Aktif Hanya memuat berkas dokumen yang sedang dibuka dan dikerjakan saat itu juga. Berukuran terbatas tapi sangat cepat dijangkau tangan (~10 nanodetik). Bersifat volatile.
Storage (HDD/SSD) = Lemari / Gudang Arsip Raksasa Menyimpan seluruh file dokumen dan OS secara permanen walau listrik mati (non-volatile). Kapasitasnya raksasa, tetapi butuh waktu lebih lama untuk mengambilnya (~10 milidetik).

D. SIKLUS FETCH - DECODE - EXECUTE (FDE)

Bagaimana CPU mengolah data? Jantung CPU berdetak miliaran kali per detik melalui Siklus Mesin Von Neumann yang berulang:

1

FASE 1: FETCH (Ambil Instruksi)

MAR → IR

CPU mengambil instruksi biner dari RAM berdasarkan alamat kotak memori yang ditunjuk oleh Program Counter (PC), lalu menyalinnya ke Instruction Register (IR).

2

FASE 2: DECODE (Terjemahkan Perintah)

Analisis CU

Mandor Control Unit (CU) membedah instruksi: Perintah apa yang diminta? Datanya ada di mana? Operasi apa yang harus dijalankan?

3

FASE 3: EXECUTE (Eksekusi Komputasi)

Eksekusi ALU

Mesin hitung ALU mengeksekusi aksi nyata: melakukan perhitungan angka, memindahkan data antar register, atau melakukan percabangan keputusan logika.

4

FASE 4: WRITE-BACK / STORE (Setor Hasil)

ACC → RAM

Hasil akhir dari Accumulator disetor kembali ke RAM melalui Data Bus agar siap dijemput oleh pengontrol layar monitor.

E. BUS SISTEM: JALUR KOMUNIKASI DATA

Semua komponen terhubung lewat Bus Sistem di motherboard, tapi CPU hanya boleh berkomunikasi lewat RAM — tidak pernah langsung ke Input/Output.

Data Bus

Dua Arah (Bi-directional)

Membawa muatan aktual data dan instruksi bolak-balik antara CPU dan RAM (misal mengirim angka 3 dan 5, lalu menyetor kembali angka 8).

Address Bus

Satu Arah (CPU → RAM)

CPU menentukan alamat kotak memori di RAM yang ingin dibaca atau ditulis (misal: Alamat 100, 200, atau 300).

Control Bus

Sinyal Pengendali

Membawa sinyal komando sinkronisasi dari CU, seperti sinyal READ, WRITE, detak CLOCK pulsa, dan sinyal interupsi.

F. DINAMIKA I-P-O: STUDI KASUS KALKULATOR

Mari kita bedah perjalanan nyata data saat pengguna menghitung 3 + 5 = 8 pada sistem kalkulator komputer!

Langkah 1: Mengetik Angka 3

Sinyal tombol '3' dari keyboard dititipkan dulu di RAM Alamat 100.

Langkah 2: Mengetik Operator '+'

Kode operasi penambahan (ADD) disimpan di RAM Alamat 200.

Langkah 3: Mengetik Angka 5

Sinyal tombol '5' disimpan di RAM Alamat 101.

Langkah 4: CPU Menarik Data & MENUNGGU Perintah '='

Data ditarik ke Register A dan B. CPU TIDAK LANGSUNG MENJUMLAHKAN! Mandor CU menahan eksekusi menunggu pemicu tombol '=' ditekan.

Langkah 5: Tombol '=' Ditekan → ALU Mengeksekusi

CU mengirim perintah hitung ke ALU → ALU menjumlahkan $3 + 5 = 8$ di Register Accumulator.

Langkah 6: Setor Balik ke RAM Alamat 300

Hasil angka 8 ditulis balik ke RAM Alamat 300 via Data Bus. CPU tidak pernah mengirim langsung ke monitor!

Langkah 7: Layar Monitor Melakukan Polling RAM

Display controller membaca RAM Alamat 300 (polling 60x/detik) → matriks LED/LCD menyala membentuk angka '8' dalam tempo kurang dari 1 milidetik!

G. ISTILAH PENTING (GLOSARIUM)

Glosarium konsep esensial Arsitektur Sistem Komputer berdasarkan modul pembelajaran John von Neumann:

Stored-Program Concept

Prinsip John von Neumann (1945) di mana instruksi program dan data disimpan bersama di RAM, menggantikan proses rewiring kabel manual era ENIAC.

CPU itu Sombong

Prinsip sentralisasi memori di mana CPU hanya mau berkomunikasi langsung dengan RAM via Bus Sistem, dan menolak berhubungan langsung dengan I/O.

Transit Hub (RAM)

Peran RAM sebagai titik temu sentral wajib tempat semua data masuk dititipkan sebelum diambil CPU, dan tempat hasil olahan disimpan sebelum ditampilkan ke layar.

Volatile vs Non-Volatile

RAM bersifat volatile (data lenyap saat mati listrik), sedangkan Storage HDD/SSD bersifat non-volatile (data tersimpan permanen).

Polling Layar

Mekanisme di mana display controller memeriksa kotak memori RAM secara berkala (misal 60 kali per detik) untuk merender piksel ke monitor.

Tim 3 Pemain CPU

Tiga unit inti di dalam CPU: Control Unit (CU sebagai mandor pengarah), ALU (sebagai mesin hitung), dan Register (sebagai catatan saku cepat).
